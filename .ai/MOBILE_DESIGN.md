## 1. หลักการออกแบบ

1. **3 วินาทีรู้สถานะทั้งบ้าน / 1 แตะจัดการงานด่วน** (PDF2)
2. **ผู้ใช้ 3 แบบในแอปเดียว** — ต้องสลับโหมดได้ ไม่ใช่ทำแอปแยก
3. **ซ่อนสิ่งที่ไม่มีสิทธิ์** ดีกว่าแสดงแล้วกดไม่ได้ (ยกเว้น action ที่ผู้ใช้ควรรู้ว่ามีและขอสิทธิ์ได้)
4. **ห้ามแสดง PHI บนหน้าจอล็อก/notification** (N-02)
5. **ผู้สูงอายุต้องใช้ได้จริง** — ตัวอักษรใหญ่ คอนทราสต์สูง ไม่มีกราฟ
6. **ทุกหน้าจอมี 5 สถานะ**: loading / empty / data / error / offline

## 2. Flow หลัก

### 2.1 ลงทะเบียน (Register)

```
Splash
 → Intro (3 สไลด์, ข้ามได้)
 → Consent (A: ข้อกำหนดการใช้บริการ) + (B: ความยินยอมประมวลผลข้อมูลสุขภาพ)
 → Register: อีเมล+รหัสผ่าน | เบอร์โทร | Google
 → Phone (ถ้ายังไม่มี)
 → OTP (6 หลัก, หมดอายุ 5 นาที, ส่งซ้ำได้หลัง 60 วิ)
 → Setup PIN (6 หลัก)
 → Confirm PIN
 → สร้าง Workspace หรือเข้าร่วมด้วยรหัสเชิญ
 → Profile Select (แนวนอนสไตล์ Netflix: ภาพรวมทั้งบ้าน / คุณพ่อ / คุณแม่ / ฉัน)
 → Dashboard
```

**หมายเหตุ**
- Consent B **แยกจาก** Consent A (F-12) — ผู้ใช้ปฏิเสธ B ได้แต่จะใช้ฟีเจอร์สุขภาพไม่ได้
- ระหว่างทางทุกขั้นต้อง **resume ได้** (เก็บ `onboarding_step` ใน secure storage)
- ถ้าเข้าร่วมด้วยรหัสเชิญ → ข้ามการสร้าง workspace แต่ยังต้องเลือก profile

### 2.2 เข้าสู่ระบบ (Login)

```
Splash → PIN (หรือ Biometric ถ้าเปิดไว้)
 → Workspace (ถ้ามี >1)
 → Profile Select
 → Dashboard
```

- PIN ผิด 5 ครั้ง → ล็อก 5 นาที + ต้อง OTP
- Biometric เป็น convenience — fallback เป็น PIN เสมอ
- Session หมดอายุ → กลับไป PIN โดยคงสถานะหน้าจอเดิม (ถ้าปลอดภัย)

### 2.3 เพิ่มผู้รับการดูแล (Dependent / Proxy)

```
Family & Access → [+ เพิ่มสมาชิก]
 → เลือก: มีบัญชีของตัวเอง | ไม่มีบัญชี (ผู้รับการดูแล)
 → [ไม่มีบัญชี] กรอกชื่อ/วันเกิด/กลุ่มเลือด/แพ้ยา
 → ระบุความสัมพันธ์ (ลูก / คู่สมรส / ผู้ปกครอง / ผู้ดูแล / อื่น ๆ)
 → เลือกระดับอำนาจ:
      L1  ช่วยประสานงาน (ไม่เห็นข้อมูลสุขภาพ)
      L2  ผู้แทน — เข้าถึงข้อมูลสุขภาพได้
      L3  ผู้แทน + การตัดสินใจความเสี่ยงสูง
 → [L1] ยืนยัน OTP → เสร็จสิ้น (ใช้งานได้ทันที)
 → [L2/L3] เข้าสู่ขั้นยืนยันอำนาจ (§2.4)
```

> ผู้ใช้ต้องเห็นคำอธิบายระดับก่อนเลือก และสลับภายหลังได้ (ยกระดับต้องผ่านการตรวจ) — ดู [ADR-015](DECISIONS.md#adr-015--หลักฐานอำนาจผู้แทน-3-ระดับตามความเสี่ยง) และ [ADR-009](DECISIONS.md#adr-009--dependent-profile-ไม่ต้องเพิ่ม-role-ใหม่)

### 2.4 ขั้นยืนยันอำนาจผู้แทน (L2 / L3)

```
[1] เลือกประเภทผู้ถูกแทน:  ผู้เยาว์  |  ผู้ใหญ่
        │
        ├─ ผู้เยาว์  → แนบ สูติบัตร/ทะเบียนบ้าน + บัตร ปชช. ผู้แทน
        └─ ผู้ใหญ่   → แนบ คำสั่งศาล  หรือ  หนังสือมอบอำนาจที่รับรอง
[2] ยืนยันตัวตนผู้แทน (OTP + PIN)
[3] ตรวจสอบข้อมูลที่แนบ (ดูตัวอย่างที่ถูกต้องได้)
[4] ส่งคำขอ → สถานะ "รอตรวจสอบ" (L2 ≤2 วันทำการ · L3 ≤5 วันทำการ)
[5] ผลการตรวจ
        ├─ อนุมัติ   → ระดับใหม่มีผลทันที + แจ้งเตือนเจ้าของข้อมูล
        └─ ไม่อนุมัติ → แสดงเหตุผล + ปุ่ม "ส่งใหม่" / "ติดต่อทีมงาน"
```

**ระหว่างรอตรวจสอบ:** ผู้ใช้ยังอยู่ใน **L1** (มอบหมายงานได้ แต่ไม่เห็นเวชระเบียน) — ต้องบอกให้ชัดว่า "ระหว่างนี้ใช้ได้เฉพาะการประสานงาน"

**L3 เพิ่ม:** ต้องมีผู้ตรวจ 2 คน + แจ้งเหตุผลความจำเป็น + ยืนยันตัวตนซ้ำ

**สถานะที่ต้องออกแบบ:** `draft` · `submitted` · `under_review` · `verified` · `rejected` · `expired` · `revoked`

**แบนเนอร์ที่ต้องมี**
| สถานการณ์ | ข้อความ |
|---|---|
| รอตรวจสอบ | "คำขอของคุณอยู่ระหว่างตรวจสอบ (โดยปกติ 2 วันทำการ) — ใช้ฟีเจอร์ประสานงานได้แล้ว" |
| จะหมดอายุใน 30 วัน | "สิทธิ์ผู้แทนของคุณจะหมดอายุใน 30 วัน — ยืนยันซ้ำ" |
| เจ้าของข้อมูลมีบัญชีแล้ว | "คุณแม่มีบัญชีของตัวเองแล้ว — ยืนยันหรือส่งคืนสิทธิ์ภายใน 30 วัน" |
| ถูกระงับ | "สิทธิ์ผู้แทนถูกระงับชั่วคราว — ติดต่อทีมงาน" |

**ข้อความที่ห้าม**
- ห้ามบอกว่าผู้ใช้ "เป็นผู้ปกครองโดยชอบธรรม" ก่อนผ่านการตรวจ — ใช้ "ผู้แทน (รอตรวจสอบ)"
- ห้ามแสดงชื่อไฟล์เอกสารในรายการทั่วไป (แสดงแค่ประเภท + วันที่)
- ห้ามให้ AI อ่าน/สรุปเอกสารอำนาจตามกฎหมาย

## 3. Information Architecture (5 แท็บ)

| # | แท็บ | เนื้อหา | เหตุผล |
|---|---|---|---|
| 1 | **หน้าแรก** (Dashboard) | 5 โซน (§4) | งานหลัก: รู้สถานะ |
| 2 | **งานดูแล** (Care CRM) | ปฏิทินครอบครัว, รายการงาน, ตารางเวร, นัดหมาย, บันทึกส่งเวร | งานประสาน + นัด รวมกัน (ADR-004) |
| 3 | **(+)** ปุ่มกลาง | บันทึกความดัน/น้ำตาล · ถ่ายรูปอาการ · ถ่ายซองยา · ฝากงานให้คนในบ้าน | ทางลัดงานที่ทำบ่อยที่สุด |
| 4 | **คลังสุขภาพ** (Health Vault) | ประวัติแยกหมวด, กราฟ 30/90 วัน, แพ้ยา, ยาปัจจุบัน, ผลแล็บ, AI ช่วยสรุป | ค้นข้อมูลเชิงลึก |
| 5 | **ครอบครัวและสิทธิ์** | สมาชิก, คำเชิญ (QR), ผู้ดูแลชั่วคราว, สิทธิ์รายหมวด, **ประวัติการเข้าถึง** | ควบคุมความเป็นส่วนตัว |

**Chat AI** — ไม่ใช่แท็บ (ADR-004): ไอคอนใน top bar + การ์ด "ถามผู้ช่วย AI" ใน Home
**Notification** — ไอคอนกระดิ่งใน top bar ทุกแท็บ
**SOS / Emergency Card** — ปุ่มแดงใน top bar (เฉพาะเมื่อ break-glass เปิดใช้งาน)

## 4. Dashboard — 5 โซน

เรียงบนลงล่างตามความสำคัญ:

### โซน 1 · Family Switcher & Status Pill Bar
```
[ ภาพรวมทั้งบ้าน ] [ คุณพ่อ (76) • ] [ คุณแม่ (72) • ] [ ฉัน ]
```
- **Health Status Ring** รอบ avatar: 🟢 ปกติ · 🟡 มีงานค้าง/ค่าเริ่มผิดปกติ · 🔴 ต้องแก้ไขทันที
- **กฎสีแดง:** ใช้เฉพาะ "ต้องมีคนทำอะไรภายในวันนี้" — ห้ามใช้กับค่าที่สูงเพียงเล็กน้อย
- ขวาบน: 🔔 แจ้งเตือน · **SOS** (แดง)

### โซน 2 · Priority Alert & Escalation Banner
- **แสดงเฉพาะเมื่อมีเรื่องต้องตัดสินใจ** (conditional rendering) — ปกติซ่อน
- การ์ดมี: ชื่อบุคคล, เหตุการณ์ย่อ, เวลา, ปุ่ม action ≤2 ปุ่ม
- ตัวอย่าง: `คุณพ่อ: ความดันเช้านี้ 162/94 mmHg (สูงกว่าเกณฑ์) · 08:10` → `[โทรเช็ก]` `[ดูกราฟ 7 วัน]`
- **ห้ามใส่ค่าที่ sensitive** ถ้า modal ยังไม่ผ่านการตรวจสิทธิ์

### โซน 3 · ภารกิจวันนี้
- แบ่งช่วง: เช้า / กลางวัน / เย็น / ก่อนนอน + progress bar `สำเร็จ 3/6`
- **Task Card Anatomy:**
  | ส่วน | ตัวอย่าง |
  |---|---|
  | เจ้าของงาน | `[คุณพ่อ]` |
  | กิจกรรม | `กินยาหลังอาหารเช้า (3 รายการ)` + ไอคอนเม็ดยาจริง |
  | ผู้รับผิดชอบ | `[ดูแลตัวเอง]` / `[มอบหมาย: น้องชาย]` |
  | ปุ่ม | `[กินยาแล้ว]` (1 แตะ) / `[ข้าม]` (ต้องระบุเหตุผล) |
- งานวัดค่า → ปุ่ม `[กรอกตัวเลข]` หรือ `[ถ่ายรูปหน้าจอเครื่องวัด (AI OCR)]`

### โซน 4 · Vital Signs Snapshot (2×2)
| การ์ด | เนื้อหา |
|---|---|
| ความดัน + ชีพจร | `162/94 mmHg · 76 bpm` + สถานะ + `[กราฟแนวโน้ม]` |
| น้ำตาล | `112 mg/dL (หลังอดอาหาร)` |
| Adherence 7 วัน | `92% (13/14 มื้อ)` + `พลาดมื้อเย็น 1 ครั้ง` |
| น้ำหนัก / อาการล่าสุด | `64.5 kg` หรือข้อความอาการ |

### โซน 5 · นัดหมายถัดไป + Doctor Brief
- การ์ดนัด: วันที่, แผนก, โรงพยาบาล, ผู้รับผิดชอบพาไป
- **ปุ่มหลัก:** `[สร้างใบสรุป 1 หน้าให้คุณหมอ (PDF/QR)]`
- ถ้ายังไม่มีสิทธิ์ export → ปุ่มแสดงแบบ disabled + "ขอสิทธิ์จากเจ้าของข้อมูล"

## 5. Permission-Aware Rendering

**หลัก:** ซ่อน (hide) vs ปิดใช้งาน (disable) มีกฎชัดเจน

| กรณี | วิธี | เหตุผล |
|---|---|---|
| ไม่มีสิทธิ์อ่านข้อมูลประเภทนั้นเลย | **ซ่อน** ทั้งการ์ด | ไม่ควรรู้ว่ามีข้อมูล |
| มีสิทธิ์อ่านแต่ไม่มี action (เช่น export) | **disable + tooltip "ต้องขอสิทธิ์"** | ผู้ใช้ควรรู้ว่ามีฟีเจอร์ |
| ข้อมูลมีอยู่แต่ถูกจำกัดด้วยเวลา | **แสดง + badge "หมดสิทธิ์วันที่…"** | สื่อสารชัด |

**ตัวอย่าง 3 มุมมองของผู้ป่วยคนเดียวกัน (PDF2 §5):**

| Persona | เห็น | ไม่เห็น |
|---|---|---|
| **ลูกสาว (Primary Coordinator)** | ทุกการ์ด, ผลแล็บ, ปุ่ม export | — |
| **ผู้ดูแลรายวัน** (`health_measurement.create`, `health_measurement.read`, `care_task.complete`) | งานในกะของตน, ช่องกรอกค่าความดัน | ผลแล็บย้อนหลัง, บันทึกส่วนตัว, ปุ่ม export |
| **ญาติช่วยขับรถ** (`task_id` เดียว) | การ์ดนัด + นำทาง + ยืนยันส่งถึงบ้าน | การ์ดสัญญาณชีพ, รายการยา, ทุกอย่างอื่น |

**บังคับใช้ที่ฝั่งไหน:** UI เป็นแค่การซ่อน — **backend ต้องกรองทุกครั้ง** (AP-003)

## 6. Elder Mode / Simplified Dashboard

เปิดด้วยสวิตช์ "โหมดหน้าจอย่อ" หรืออัตโนมัติเมื่อเลือกโปรไฟล์ผู้สูงอายุ

| องค์ประกอบ | ข้อกำหนด |
|---|---|
| ตัวอักษร | ≥ 20 pt, คอนทราสต์ ≥ 4.5:1 |
| จำนวนปุ่มต่อหน้า | **≤ 3** |
| กราฟ/ตาราง | **ตัดออกทั้งหมด** |
| การ์ด | **Single-Focus**: แสดงเฉพาะสิ่งที่ต้องทำตอนนี้ |
| ปุ่มหลัก | `[กดเมื่อกินยาแล้ว]` ใหญ่เต็มความกว้าง |
| ภาพประกอบ | รูปเม็ดยาจริง/ซองยาที่ลูกหลานถ่ายไว้ |
| ภาพวัดค่า | `[ถ่ายรูปค่าความดัน]` เปิดกล้องทันที ไม่ต้องพิมพ์ |
| ข้อความตอบรับ | มีเสียงอ่าน: "บันทึกการกินยาเช้าเรียบร้อยแล้วค่ะ" |
| ติดต่อ | Speed dial ลูกหลาน + SOS ล่างสุด |
| การยืนยัน | **ไม่มีการยืนยันซ้ำ** สำหรับ routine (กัน Click Fatigue) |

## 7. Notification & Copy (ห้าม PHI)

| สถานการณ์ | ข้อความที่ **อนุญาต** | ห้าม |
|---|---|---|
| เตือนงาน | `ถึงเวลากินยาหลังอาหารเช้า (3 รายการ)` | `กินยา Amlodipine 5mg` |
| งานค้าง | `ยังไม่มีบันทึกงาน "วัดความดันเช้า" (เลยกำหนด 30 นาที)` | `ความดัน 168/96 ยังไม่ได้บันทึก` |
| Escalation | `คุณพ่อมีงานที่ยังไม่ยืนยัน 1 รายการ` | `คุณพ่อลืมกินยาความดัน` |
| นัด | `พรุ่งนี้ 09:00 น. พบแพทย์` | `นัดติดตามโรคไตระยะ 3` |
| Lock screen | ทุกข้อความต้องผ่านเกณฑ์ข้างต้น | ค่าแล็บ/ชื่อโรค/ชื่อยา |

**ปุ่มใน LINE rich message:** มีเฉพาะ `[ยืนยันแล้ว]` / `[ขอให้ช่วย]` (postback) — ไม่มีข้อมูลสุขภาพในข้อความ (ADR-003)

## 8. Design tokens & components

### 8.1 สี
| token | ใช้ |
|---|---|
| `success` (เขียวมินต์) | งานสำเร็จ, ปกติ |
| `warning` (เหลืองอำพัน) | งานค้าง, ค่าเริ่มผิดปกติ |
| `danger` (แดง) | ต้องแก้ทันที, SOS, break-glass |
| `info` (ฟ้าอ่อน) | ข้อมูลทั่วไป, ลิงก์ |
| `surface` (ขาวนวล) | พื้นหลัง — ลดความเครียด (PDF2 §6.3) |

## 9. States ที่ต้องออกแบบทุกหน้า

| state | ต้องแสดง |
|---|---|
| loading | skeleton (ไม่ใช่ spinner กลางจอ) |
| empty | คำอธิบาย + ปุ่มสร้าง (ไม่ใช่หน้าว่าง) |
| error | ข้อความไม่เปิดเผยข้อมูล + ปุ่ม retry + trace id |
| offline | แบนเนอร์ + งานที่บันทึกในคิว ("จะซิงก์เมื่อออนไลน์") |
| forbidden | ข้อความสุภาพ + ปุ่ม "ขอสิทธิ์" (ถ้ามี flow) |
| revoked | "สิทธิ์ของคุณถูกเปลี่ยน" + ปุ่มกลับหน้าหลัก (ไม่ค้างหน้าเปล่า) |

## 10. Offline & Sync

- งาน `routine` บันทึกได้ตอนออฟไลน์ → เก็บ queue + `idempotency_key`
- งาน `clinical` **ห้าม** complete ตอนออฟไลน์ (ต้องมีหลักฐาน + verify)
- conflict: ใช้ `version`; ถ้า server version ใหม่กว่า → ให้ผู้ใช้เลือก (แสดง diff)
- ห้าม cache ข้อมูลสุขภาพในเครื่องเกิน 24 ชม. และต้องเข้ารหัส (`secure storage`/SQLCipher)

## 11. Accessibility & Performance

- รองรับ text scale 200% โดยไม่ตัดข้อความ
- ทุกปุ่มมี `Semantics(label:)`; ภาพมี label
- ระยะแตะ ≥ 48×48 dp
- ห้าม animation ที่กระพริบ > 3 ครั้ง/วินาที
- Cold start < 2.5s; หน้า Dashboard ต้องแสดง skeleton < 300ms
